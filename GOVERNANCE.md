# Project governance

Proposed working process for AI Governance Lab. This is an independent prototype preparing for a possible FINOS contribution; no FINOS acceptance or bank endorsement is asserted.

## Roles and decisions

The proposed domain/architecture lead is Yang Wang, methods lead Jiaman Li, and delivery coordinator Ning Wang. Appointment, time commitment and public affiliation wording require confirmation. A release/implementation maintainer and independent reviewers remain to be named. Do not infer merge rights from this document.

Contributors may submit code, tests, synthetic scenarios, reviewed methods, docs, accessibility improvements and source-versioned risk mappings. Maintainers are selected for sustained reviewed contributions, reliability and willingness to support users, with a recorded decision by existing maintainers. Institutional affiliation is not a substitute for contribution.

Design changes start with an issue describing the problem, evidence, proposed behavior, alternatives, compatibility and owner. Scientific behavior changes need domain and methods review; code needs engineering review. Record disagreement and resolve by evidence or a bounded experiment. If consensus fails, named maintainers record a decision and rationale; a safety, data-permission or unresolved scientific-validity concern blocks the affected release scope until resolved or explicitly excluded. There are no appointed voting maintainers yet.

## Releases and reviews

Small documentation/UI changes need one independent reviewer. Changes to engine behavior, schemas or empirical claims need an engineering maintainer plus a domain/methods reviewer; authors cannot be their own sole reviewers. Release owners record test results, schema compatibility, known limitations and dependency/model versions. A bank's private validation/deployment decision does not authorize public disclosure, and open-source acceptance does not approve bank deployment.

Keep public decisions and contributor discussions in repository issues/PRs once a public repository is configured. Do not post bank records, personal data, credentials or confidential architecture. Respectful participation and technical criticism are expected; before public launch, maintainers must appoint moderation contacts and adopt a complete code of conduct and reporting process.

## Security and rights readiness

Before accepting public users, enable a private security-reporting channel and publish a monitored SECURITY.md with support scope and response ownership. No reporting address is invented here. Do not put exploit details or secrets in public issues.

Current code license remains MIT. The project has not enabled FINOS DCO/CLA automation or adopted FINOS governance. Track copyright holders and dependency/data rights now; coordinate a reviewed license and contribution-process transition if accepted. Required hosted repository settings and legal clearances are release backlog items, not completed by these local files.
